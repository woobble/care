# Controlled pilot readiness

Use this checklist with the [operations runbook](runbooks/pilot-operations.md). **Implemented** describes repository behavior. **Verified** refers only to the named automated or isolated check; it does not mean a live production deployment is verified.

| Area                                          | Status                          | Evidence or action                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                     |
| --------------------------------------------- | ------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| OIDC authentication and HTTPS session cookies | Implemented                     | Authentik remains the OIDC provider; Caddy terminates HTTPS; production URLs and callback are validated. Verify actual DNS, certificates and Authentik settings at deployment.                                                                                                                                                                                                                                                                                                                                                                         |
| First tenant administrator                    | Implemented                     | One-time, audited production bootstrap creates the initial tenant and built-in roles only on a fresh database. Use a real Authentik subject and protect the superuser migration credential.                                                                                                                                                                                                                                                                                                                                                            |
| Tenant authorization and RLS                  | Verified                        | Existing API integration tests exercise role, resource-scope and cross-tenant denial paths using non-owner database roles. Review changes to those boundaries with the same tests.                                                                                                                                                                                                                                                                                                                                                                     |
| Private document access and integrity         | Verified                        | Existing API integration coverage checks authorization and SHA-256 behavior. The recovery drill additionally checks restored object bytes and metadata.                                                                                                                                                                                                                                                                                                                                                                                                |
| Production Compose isolation                  | Implemented                     | Database, Redis, worker and storage ports are removed from host publishing; only Caddy publishes 80/443. The deployment host and network policy still require operator configuration.                                                                                                                                                                                                                                                                                                                                                                  |
| Production secrets and configuration          | Implemented                     | Secret-file loading, production URL/secret checks, restricted `.env.production`, SMTP validation and operator preflight are available. Real secret files and external services require operator configuration.                                                                                                                                                                                                                                                                                                                                         |
| Authentication endpoint rate limiting         | Requires Operator Configuration | Caddy has no explicit rate-limit policy. Confirm Authentik and Better Auth protections and add edge controls appropriate to the public host before exposing a pilot.                                                                                                                                                                                                                                                                                                                                                                                   |
| Database migration startup                    | Implemented                     | Checksummed transactions and an advisory lock serialize migration runs; Compose waits for migration completion and API health. An incompatible migration still requires a forward fix or restore.                                                                                                                                                                                                                                                                                                                                                      |
| Paired database and object recovery           | Implemented                     | Recovery sets contain both PostgreSQL databases, roles, all S3 objects, metadata and checksums. Create them during a write-quiescence window.                                                                                                                                                                                                                                                                                                                                                                                                          |
| Recovery drill                                | Verified                        | On 2026-10-12, recovery set `care-20261012T102233394Z-bdaaf486` restored to a fresh PostgreSQL 18.6 cluster and empty bucket in 13.081 seconds. The operator verified migration checksums, 106 forced-RLS tables, selected counts (1 tenant, 48 clients, 11 invoices, 6 payments, 9 claims, 16 document artifacts), and all 40 objects' database references, bytes and metadata. The earlier isolated drill also confirmed tenant isolation under a non-owner role. Both drills used synthetic data; no RTO/RPO or live production restore is claimed. |
| API and worker health                         | Implemented                     | Liveness/readiness report database, storage, heartbeat and optional routing. Preflight reports scheduler history and outbox backlog. A real deployment must confirm alert ownership and response.                                                                                                                                                                                                                                                                                                                                                      |
| Application-specific metrics and alerting     | Requires Operator Configuration | API/worker Prometheus endpoints report request volume and duration, dependency readiness, document-generation failures, scheduler/outbox health, backlog and process metrics. When the optional observability profile is enabled, production includes a starter Grafana dashboard and availability/operations alert rules; review their thresholds and configure notification routing for the pilot. The opt-in production Prometheus/Grafana services bind to loopback. Metric labels contain no tenant or client identifiers.                        |
| Session logout across Authentik               | Not Yet Supported               | Care Platform logout clears its own session; provider logout is disabled and does not invalidate the Authentik browser session. Set operator session policy accordingly.                                                                                                                                                                                                                                                                                                                                                                               |
| Email invitations from the Care Platform      | Not Yet Supported               | Tenant invitations are recorded but not sent. Operators must deliver invitations through an approved process. Authentik SMTP is configured for Authentik mail.                                                                                                                                                                                                                                                                                                                                                                                         |
| Payer-specific billing and claims             | Requires External/Legal Review  | Verify fee schedules, invoice wording, claim formats, payer agreements and local accounting requirements with the pilot's actual counterparties. There is no automated payer transmission or payment gateway.                                                                                                                                                                                                                                                                                                                                          |
| Data retention and erasure                    | Requires External/Legal Review  | Apply the [data-lifecycle inventory](security/data-lifecycle.md) to real policy and statutory requirements before importing real data. No universal cascade deletion or GDPR certification is provided.                                                                                                                                                                                                                                                                                                                                                |
| Backup destination encryption and retention   | Requires Operator Configuration | Put backups on an encrypted, access-restricted destination; set retention based on approved operational and legal policy.                                                                                                                                                                                                                                                                                                                                                                                                                              |
| Browser regression                            | Verified                        | The isolated Authentik browser journey passed on 2026-10-12 (1 test, 2.5 minutes), covering the main office/caregiver/billing workflow, retired navigation in English and German, and former-caregiver reassignment denial. It emitted a non-blocking React hydration warning for a service-agreement details element.                                                                                                                                                                                                                                 |
| Web production image                          | Verified                        | The standalone web image built successfully with Docker on 2026-10-12, including production compilation, TypeScript, and route generation. This does not verify a deployment or the production environment.                                                                                                                                                                                                                                                                                                                                            |
| Production smoke test                         | Requires Operator Configuration | Verify Authentik login, Office load, client lookup, assigned caregiver access, document retrieval, worker status and dependency readiness with synthetic data after deployment.                                                                                                                                                                                                                                                                                                                                                                        |

Do not label the platform fully production-ready based on code or CI results. Begin with synthetic data, one provider and a named operator. Review the first real workflow with the provider before expanding staff or data volume.
