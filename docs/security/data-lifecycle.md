# Data lifecycle inventory

This inventory describes technical storage and deletion behavior. It is not a legal retention schedule. The provider must set retention periods with its data-protection and legal advisers before using real client data.

| Data                                    | Storage and access                                                                             | Current lifecycle                                                                                                                                                                                                   |
| --------------------------------------- | ---------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Active operational records              | Tenant-scoped PostgreSQL tables protected by API scope checks and forced RLS                   | Records can be archived or marked inactive in supported workflows. There is no universal client cascade delete.                                                                                                     |
| Billing and benefits                    | Tenant-scoped PostgreSQL ledgers, payer settings, claims, invoices, payments and corrections   | Issued invoice snapshots and financial history are immutable or append-only. Corrections are recorded as new history. No automatic legal-retention deletion is implemented.                                         |
| Care documentation and visit evidence   | PostgreSQL narrative records, immutable evidence-package snapshots and acknowledgement history | Finalized documentation and evidence history are preserved; amendments and revocations append history. There is no automatic deletion policy.                                                                       |
| Signatures and generated documents      | Private S3-compatible storage; database rows retain object keys and SHA-256 hashes             | Authorized retrieval verifies hashes. Backup includes current objects and metadata. There is no automatic orphan purge.                                                                                             |
| Audit and outbox                        | PostgreSQL audit rows and transactional outbox                                                 | Audit history is retained. Delivered outbox rows are not automatically purged by the worker. Avoid placing narrative care text or credentials in audit metadata.                                                    |
| Temporary caregiver form drafts         | Browser `sessionStorage`, scoped by user, tenant, visit, form and server revision              | Draft contents expire after 24 hours and stale, malformed or inaccessible drafts are purged when the caregiver draft scope loads. Browser storage is not encrypted and is accessible to the active browser profile. |
| Retired clinical and medication schemas | PostgreSQL schemas renamed to `retired_*`; `care_app` access was revoked                       | Existing data is preserved, not used by active modules, and included in full database backups. Drop only after a separate, documented data review and approval.                                                     |
| Recovery sets                           | Restricted backup directory containing both database dumps and all bucket objects              | Default operational retention is 30 days. Pruning keeps the newest checksum-verified set, skips incomplete sets and requires `--apply`; backups can retain deleted or superseded business data until they expire.   |

The recovery manifest counts object keys not referenced by the tracked document, invoice and signature tables. It reports orphan objects but never deletes them. Investigate the source, authorization and retention basis before any manual removal.

For an access, correction, deletion or anonymization request, verify the requester's identity and authority, identify affected operational, financial, evidence, audit, retired-schema and backup records, assess statutory retention and evidence-preservation duties, then have an authorized operator record and review the decision. Restore or inspect backups only in an isolated environment. Do not promise that deleting an active record also removes its copies from retained backups.

Legal and privacy review is required to define retention periods for care notes, signatures, billing and payer records, audit logs, retired schemas and backups; to determine whether an individual request permits erasure or requires evidence preservation; and to approve the pilot's lawful basis, notices, data-processing agreements and hosting region. The software does not claim certified GDPR compliance.
